# 架构说明

## 分层

```
┌──────────────────────────────────────────────┐
│ index.html           单页应用（零构建）        │
│   体系列表 = 本地内核 15 个 + 可选后端 N 个    │
└───────────────┬──────────────────────────────┘
                │ 同源 import（浏览器直载 ES Module）
┌───────────────▼──────────────────────────────┐
│ kernel/core      历法 / 干支 / 八卦 / 五行     │  纯函数，可单测
│ kernel/engines   15 个体系，各自独立           │  一体系一文件
│ kernel/data      历法数据 1900–2100            │  20 KB 静态表
│ kernel/ai        解读层（BYO key，不参与起局）  │
│ kernel/ui        模块注册表 + 表单/结果渲染     │
└───────────────┬──────────────────────────────┘
                │ 可选：HTTP
┌───────────────▼──────────────────────────────┐
│ api/xuanxue_api.py  FastAPI 统一网关           │
│   本地重型引擎（星象/天文）+ 上游网关转发       │
└──────────────────────────────────────────────┘
```

## 三个关键决策

### 1. 零依赖、零构建

没有 webpack/vite，没有 npm 包。`index.html` 里一行 `<script type="module">` 直接 import `./kernel/`。
理由：术数算法是一次性计算、确定性输出，**不值得引入构建链**；零构建让「改一个历法常数 → 刷新即见」
成为可能，也让这个仓库十年后还能被人打开就跑。

### 2. 算与说分离

`kernels/engines/*.js` 只做计算，绝不调用模型。`kernel/ai/ai.js` 只读计算结果。
这条边界解决的是**可信度**问题：排盘可复现，解读可替换（换模型、换提示词、干脆不用 AI）。
`ai.js` 里 `apiKey: ''` 默认空 —— 不内置任何密钥，使用者自己填。

### 3. 历法口径显式化

`core/calendar.js` 的数据源是一个 20 KB 的静态表（1900–2100，每年 24 节气编码为「距当年 1 月 1 日
00:00 的分钟数」的 20bit 值）。这样做的好处是：口径写死在数据里、可被 diff、可被替换成别的流派，
而不是藏在某个第三方库的黑盒中。

## 加一个新体系要改什么

1. 在 `kernel/engines/` 加一个文件，导出一个纯函数：`(input) => result`。
2. 在 `kernel/ui/modules.js` 的注册表里加一项（id / 名称 / 分类 / 表单字段）。
3. 完事 —— 表单、渲染、AI 解读提示词都由注册表驱动，不用改 UI 代码。

## 测试建议

引擎是纯函数，最省事的验证方式是「同一组输入 → 冻结快照」：

```js
import { paipanBazi } from './kernel/engines/bazi.js';
const out = paipanBazi({ y: 1990, mo: 6, d: 15, h: 10, mi: 0, gender: 'M' });
console.log(JSON.stringify(out));  // 与快照比对，防止口径悄悄漂移
```
